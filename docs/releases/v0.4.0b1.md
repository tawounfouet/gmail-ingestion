# Gmail Ingestion 0.4.0b1 — Gmail History Incremental

## Status

**Beta qualified — automated qualification complete.**

This slice connects the durable checkpoint control plane introduced in `0.4.0a1` to Gmail
`users.history.list`.

## Objective

Retrieve only mailbox additions that occurred after the last committed Gmail History cursor.

```text
COMMITTED CHECKPOINT
        ↓
startHistoryId
        ↓
users.history.list
        ↓
pagination
        ↓
messagesAdded[]
        ↓
MESSAGE_ADDED
        ↓
messages.get(full)
        ↓
persist
        ↓
CANDIDATE
        ↓
COMMITTED
```

## Gmail source contract

The beta calls:

```text
users.history.list(
    userId="me",
    startHistoryId=<committed history_id>,
    pageToken=<page token>,
    maxResults=<configured>,
    historyTypes=["messageAdded"]
)
```

The same `startHistoryId` is retained across all pages. Pagination advances only through
`pageToken`.

The final response `historyId` is the candidate output checkpoint even when no
`messagesAdded` events are returned.

## Event model

Each `messagesAdded[]` entry becomes one elementary event:

```text
GmailHistoryEvent
├── event_id
├── account_id
├── history_id
├── event_type = MESSAGE_ADDED
├── message_id
├── thread_id
├── label_id = null
├── event_ordinal
├── source_page_token
├── observed_at
└── run_id
```

The event ID is deterministic from the natural event key.

The generic `history.messages[]` collection is intentionally not used because Gmail exposes
specific change-type fields.

## Persistence order

```text
1. RAW History page
2. normalized MESSAGE_ADDED event(s)
3. hydrated message(s), format=full
4. candidate checkpoint
5. committed checkpoint
6. final incremental manifest
```

No candidate is created before source changes and affected messages are durably persisted.

## Failure invariant

If history/event/message persistence fails:

```text
previous COMMITTED remains authoritative
candidate for the failed run does not advance it
```

This preserves at-least-once replay semantics for a later retry.

## Expired history

The API adapter maps Gmail HTTP 404 for an invalid or expired `startHistoryId` to:

```text
GmailHistoryExpiredError
```

The application layer then:

```text
invalidate committed checkpoint
→ persist FULL_RESYNC_REQUIRED evidence
→ raise FullResyncRequiredError
```

Automatic invocation of a Full Snapshot is deliberately deferred to the reliability/recovery
qualification slice.

## CLI

```bash
gmail-ingest incremental \
  --checkpoint-root .gmail-ingestion-control \
  --artifact-root .gmail-ingestion \
  --max-results 500
```

A committed checkpoint is mandatory.
