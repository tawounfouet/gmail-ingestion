## No semantic changes allowed during promotion

Stable promotion is **promotion-only** after the live gate.

The following contracts remain frozen:

```text
normalized_schema_version      = 1
checkpoint_schema_version      = 1
history_receipt_schema_version = 1
OAuth scope                    = gmail.readonly
RAW message hydration          = format=full
PyIngestKit                    = 2.1.0
```

If the live gate exposes a code or Gmail semantic defect, return to a prerelease candidate and
requalify before stable promotion.

## Live gate

Tool:

```text
scripts/qualify_live_incremental_sync.py
```

Runbook:

```text
docs/runbooks/LIVE_INCREMENTAL_QUALIFICATION.md
```

The stable gate is deliberately two-phase so the connector can remain `gmail.readonly` while the
operator creates bounded Gmail mutations manually.

Required observed event types:

```text
MESSAGE_ADDED
MESSAGE_DELETED
LABEL_ADDED
LABEL_REMOVED
```

Required reliability evidence:

```text
Full Snapshot recovery
History catch-up
same-run recovery
cross-run durable receipt replay
zero message rehydration during receipt replay
stable output checkpoint
secret exclusion
```

## Merge/tag discipline

Do not tag the feature-branch SHA as stable.

Sequence:

```text
final stable candidate green
→ merge PR #4 to main
→ identify exact main merge SHA
→ rebuild/verify from exact merge SHA
→ tag v0.4.0 on that SHA
→ publish GitHub Release
```

The GitHub Release artifacts and SHA256SUMS must correspond to the exact tagged source.
