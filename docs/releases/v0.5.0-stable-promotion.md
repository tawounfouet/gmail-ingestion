## Remaining real Gmail stable gate

The final gate must use bounded artifacts captured from a real Gmail mailbox.

It must demonstrate at least one occurrence of each event class:

```text
MESSAGE_ADDED      >= 1
MESSAGE_DELETED    >= 1
LABEL_ADDED        >= 1
LABEL_REMOVED      >= 1
```

The disposable qualification scenario is documented in:

```text
docs/runbooks/LIVE_PROJECTION_QUALIFICATION.md
```

The evidence harness is:

```text
scripts/qualify_live_projection.py
```

Projection qualification itself makes no Gmail API call and requires no write OAuth scope. Gmail
mutations needed to generate History evidence are performed manually against a disposable
qualification message.

## Stable promotion-only rule

Once the live gate passes, stable promotion to `0.5.0` may change only:

- package version / release metadata;
- release documentation;
- CI artifact naming where needed;
- tests that explicitly assert the prerelease version.

No projection semantic, schema, reducer, persistence or recovery change is allowed after the
live-qualified candidate without producing another release candidate.
