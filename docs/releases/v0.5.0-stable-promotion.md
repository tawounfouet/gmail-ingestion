## RC3 race invariant

Gmail may expose a `MESSAGE_ADDED` event whose message is already permanently unavailable when
the connector attempts hydration.

RC3 permits a missing RAW only when a later delete in the same deterministic projected chain proves
that the target Current State must not contain the message:

```text
MESSAGE_ADDED without RAW
        +
later MESSAGE_DELETED for same message
        ↓
safe no-op for unavailable add
        ↓
delete reducer
        ↓
target Current State excludes message
```

Without the later matching delete:

```text
MESSAGE_ADDED without RAW
        ↓
FAIL CLOSED
```

## RC5 malformed header qualification

The 0.5.0rc4 live baseline bootstrap failed while normalizing message indices [92050, 92100) with HeaderParseError. The MIME analyzer already uses tolerant individual header parsing, whereas normalized message_headers used strict parsing. RC5 aligns those paths while retaining all immutable RAW evidence. RC5 requires PR CI, exact-main CI, a bounded local diagnostic on the previously failing slice, and then full live bootstrap qualification before 0.5.0 stable promotion. The full bootstrap remains non-resumable; a separate durable segmentation fix is recommended before repeating an expensive 177,546-message run.


## RC6 segmented recovery gate

A bounded real-data diagnostic confirmed the RC5 MIME header fix on source indices [92050, 92100). RC6 introduces per-batch committed Parquet segments with SHA-256 evidence and fail-closed resume; it publishes the completed baseline manifest only after all expected segments are validated. The legacy RAW snapshot remains immutable, and no Gmail OAuth calls are required.

A successful RC6 test must prove interruption/restart skipping already-committed batches, digest tampering rejection, deterministic row counts, frozen normalized schema v1, PR and exact-main CI, and real-mailbox projection convergence. Note that the projection reader still materializes normalized state in memory; segmenting the bootstrap does not by itself make full projection out-of-core.


## RC7 full-mailbox performance gate

Real RC6 baseline bootstrap: 711 committed segments, 177,546 messages, 5,782,178
headers, 558,015 message-label relations and 2.6 GB of Parquet. The user's Mac
reports 96 GiB installed RAM and only 12 GiB free disk.

RC7 removes global list rescans per Gmail label/message event through a message-id
index. It also removes extra full-baseline reads for frontier checks and hashes
canonical projection JSON one row at a time, preserving the exact legacy digest.
Require reference reducer equivalence, canonical digest parity, PR and exact-main
CI, and real live projection/rebuild equality before stable promotion.

Physical RAM capacity alone is not available-memory evidence. Candidate Parquet
writes still need disk headroom, and the Current State reader still loads normalized
rows into Python memory. Do not qualify the stable release based on code tests alone.


## 2026-11-06 live RC7 strict historical gate: NO-GO

The real 177,546-message baseline completed on RC6 with 711/711 committed
segmented Parquet batches. RC7 initiated full projection from three committed
History delta runs to target history ID 15694719 and failed on a MESSAGE_ADDED
whose original run lacked immutable message RAW.

Subsequent redacted, local and targeted Gmail diagnostics established:

- 2,624 historic events, 510 MESSAGE_ADDED; 59 missing original RAW.
- 7 missing adds followed by later deletes within the historical delta chain.
- 52 remaining missing adds: 49 currently accessible and captured in TWO
  isolated dated recovery-evidence runs, 3 currently returning 404.
- 48 recovered full messages have matching normalized rows between two captures.
- One source payload has a different MIME body across captures, with changed
  normalized attachments and mime_parts. Its observed message historyId is
  above historical target 15694719.
- A complete, read-only 37-page Gmail History sweep returned 18,050 later
  records up to response frontier 15903015. None matched the 52-member cohort.
  Thus there is no post-target deletion evidence for any of the three 404s.
- Neither a current 404 nor later full-message recovery proves the historical
  content or label state at the target boundary.

The real-mailbox historical projection gate is **NOT QUALIFIED**. Do not
auto-skip missing messages, forge tombstones, overwrite historical runs,
declare digest equivalence sufficient, or promote the authoritative current
pointer. Keep stable 0.5.0 BLOCKED.

Architecture decision and operator priority:
`docs/decisions/2026-11-06-rc7-historical-gap-reconciliation.md`.

The post-target Gmail History cursor was valid during the diagnostic. Capture
a new COMMITTED incremental run while possible, with

did NOT itself persist a new incremental run. No full snapshot or bulk
