# Gmail Ingestion 0.4.0b2 — Deletions + Label Mutations

## Status

**Beta qualified — automated qualification complete.**

## Objective

Complete the functional Gmail History mutation vocabulary before the reliability release candidate.

```text
MESSAGE_ADDED
MESSAGE_DELETED
LABEL_ADDED
LABEL_REMOVED
```

Gmail History records are normalized into elementary events and then reduced into explicit,
persisted effects.

## Source semantics

The incremental request asks Gmail for all four specific History types:

```text
users.history.list(
    userId="me",
    startHistoryId=<committed history_id>,
    pageToken=<page token>,
    historyTypes=[
        "messageAdded",
        "messageDeleted",
        "labelAdded",
        "labelRemoved",
    ]
)
```

The generic `messages[]` field is ignored because Gmail may duplicate changes already represented
in the specific arrays.

## Elementary mapping

```text
messagesAdded[]   → MESSAGE_ADDED
messagesDeleted[] → MESSAGE_DELETED
labelsAdded[]     → one LABEL_ADDED per labelId
labelsRemoved[]   → one LABEL_REMOVED per labelId
```

Every event keeps the stable natural-key components:

```text
account_id
history_id
event_type
message_id
label_id
event_ordinal
```

## Processing state

Each event is first persisted as:

```text
processing_status = PENDING
processed_at      = null
```

Only after its effect is persisted does the same event transition to:

```text
processing_status = PROCESSED
processed_at      = <UTC timestamp>
```

This makes incomplete reducer work observable without advancing the Gmail checkpoint.

## Event reducer

```text
MESSAGE_ADDED
    → hydrate message with messages.get(format=full)
    → persist immutable RAW message

MESSAGE_DELETED
    → persist MessageTombstone

LABEL_ADDED
    → persist UPSERT_ACTIVE relation mutation

LABEL_REMOVED
    → persist DEACTIVATE relation mutation
```

The reducer is pure; persistence remains in the application/infrastructure layer.

## Tombstone contract

```text
account_id
message_id
deletion_history_id
deleted_at
source_event_id
run_id
```

## Message-label mutation contract

```text
account_id
message_id
label_id
operation
history_id
is_active
observed_at
source_event_id
run_id
```

The mutation journal is deliberately separate from the frozen normalized schema-v1 snapshot.
A later materialization can reduce these deltas into the logical `message_labels` current state
without rewriting the historical ingestion evidence.

## Duplicate handling

If the same deterministic event ID appears twice during one run:

```text
first occurrence  → reduce + persist
later occurrence  → ignore
```

The manifest records `duplicate_events_ignored`.

Cross-run replay and crash recovery remain release-candidate reliability work.

## Checkpoint safety

```text
COMMITTED H100
   ↓
History pages
   ↓
PENDING events
   ↓
effects
   ↓
PROCESSED events
   ↓
CANDIDATE H130
   ↓
COMMITTED H130
```

Any failure before candidate promotion leaves H100 authoritative.
