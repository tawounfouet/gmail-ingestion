# Gmail Ingestion 0.5.0rc8 - Source-Validated Current Reconciliation

## Status: RC8 code in qualification, STABLE 0.5.0 NO-GO

RC8 introduces a separate policy `RC8_CURRENT_OVERLAY_V1` for current-source
reconciliation. It does **not** rewrite or change the strict historical
projection produced by RC7. No release may be promoted on code tests alone.

### Evidence inherited from RC7 and source observation

- 177,546 baseline messages, 711 segmented Parquet batches and 28.44 GB

- Four committed History runs through checkpoint 15903183 and 10,826

- 67 addition events missing original event-run RAW; 9 superseded by a
  later committed delete; 58 unresolved, not necessarily unique IDs.
- Two dated recovery captures (49 accessible, 3 observed 404) are not

- Independent all-mail source inventory: 181,200 IDs with Spam/Trash

- Excluded-scope long inventory failed closed with InventoryIncompleteError.
- Mac volume reported 8.6 GiB free (100% usage) before RC8.

### Explicit behavior

- The `0.5.0rc7` projector remains strict historical; missing event-local
  RAW without a later committed delete still fails closed.
- The new RC8 source overlay uses a **separate** message view as of the
  independently observed current frontier. It is never represented as
  historical truth at an earlier `historyId`.
- Provenance identity hashes include baseline, delta sequence, observed
  frontier, source set digest, exception ledger digest and recovery capture
  digest. Private identifier lists stay outside the Git repository.
- The RC8 materializer writes only candidate data with status
  `CANDIDATE_DATASET_NOT_SOURCE_QUALIFIED`. No path invokes
  `LocalProjectionStore.promote`.
- A sample of Gmail `users.messages.get(full)` validates selected messages
  but **cannot certify complete mailbox parity**. Comparison to Gmail
  History must close a consistent observation window.
- Memory and disk checks are minimum safety gates, not full out-of-core
  support. The normalized baseline reader still creates Python lists.

### Required operator qualification

The exact steps and UUIDs are in
`docs/runbooks/RC8_SOURCE_VALIDATED_CURRENT.md`. Execute all commands on
the Mac holding the local source artifacts. Stop on any fail-closed error.
The scripts never issue a Gmail Full Snapshot automatically.

Remaining conditions before a stable GO:
1. A successful scope-aligned source inventory and durable History catchup.
2. Deduplicated reconciliation of the 58 missing-RAW events with typed
   provenance and explicit resolution of every unknown.
3. Isolated Current candidate with source identities, content references,
   physical hashes and full rebuild/replay qualification.
4. Source-to-candidate equality for IDs, active labels, thread references,
   MIME part graph and attachment metadata on the qualification scope,
   not just a sample.
5. Measured disk/RAM headroom and no unexamined incomplete artifacts.
6. Final RC8 exact-main CI PASS, redacted real mailbox qualification report,
   release review decision documented in issue #29.
