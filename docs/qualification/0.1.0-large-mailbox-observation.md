# 0.1.0 — Large Mailbox Qualification Observation

Date: 2026-10-25

## Context

A real Gmail package qualification was executed against a mailbox containing more than 177k
messages.

The package successfully completed:

```text
Desktop OAuth                         PASS
credential reuse                     PASS
users.getProfile                     PASS
labels ingestion                     PASS
137 labels discovered                PASS
138 label RAW artifacts              PASS
labels Parquet                       PASS
```

The full-message qualification was manually interrupted after real immutable RAW message files had
already been written.

## Observation

The interruption occurred while persisting `MessageDiscoveryQueue` state during hydration.

The pre-hardening implementation:

```text
discover entire mailbox
→ create one Future per pending message
→ fetch one message
→ mark state
→ rewrite full discovery queue JSON
→ repeat for every message
```

This was correct for small samples but unnecessarily expensive for a mailbox with more than 177k
messages.

## Remediation

The stable candidate now uses:

```text
persisted nextPageToken
bounded in-flight Future window
batched fetch-state checkpoints
RAW-based recovery between checkpoints
bounded live qualification sample
```

The product command `gmail-ingest snapshot` remains a full snapshot by default.

The release qualification script now defaults to a 50-message real sample and records
`mode=sample_snapshot` so qualification cannot be confused with a complete mailbox export.

## Qualification

The hardening is covered by automated tests for:

- exact discovery resume from a persisted page token;
- bounded sample scope;
- batched queue persistence;
- existing 1,001-message multi-page qualification;
- full RC regression suite.

CI run `40170995650` passed on Python 3.11, 3.12 and 3.13 with 40/40 tests.
